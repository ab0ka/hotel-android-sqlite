01 · Сала трендтері

01

Қағазсыз тіркеу

Ресепшндегі қағаз журнал планшет пен телефонға көшіп жатыр. Сондықтан есепке алу бағдарламасы ең алдымен мобильді болуы керек.

02

Офлайн жұмыс істейтін база

Интернет үзілген кезде де жұмыс тоқтамауы тиіс. SQLite базасы құрылғының ішінде орналасқандықтан, қосымша желіге мүлде тәуелді емес.

03

Динамикалық баға

Баға маусымға, бос нөмір санына қарай өзгереді. Бағаны бір рет жазып қою жеткіліксіз — UPDATE операциясы қажет.

04

Деректерге негізделген шешім

Қай нөмір табысты, қай санат бос тұрады — бұл сұрақтарға GROUP BY және JOIN сұраныстары жауап береді.

05

Шағын бизнеске қолжетімділік

Үлкен PMS жүйелері 16 нөмірлі қонақүйге қымбат. Қарапайым Android қосымшасы — нақты әрі тегін шешім.

02 · Мәселе

Әкімшінің бір күні:
дәптер, қалам және қателер

Сюжет

Таңғы сағат сегіз. Әкімшінің алдында — дәптер. Онда 16 нөмірдің бағасы, қабаты, төсек саны қаламмен жазылған. Телефон шырылдайды: «Екінші қабаттан, 40 мың теңгеден аспайтын нөмір бар ма?»

Дәптердің беттері ақтарылады. Екі минут. Қонақ күтеді. Келесі қоңырау: «Люкс нөмірлердің орташа бағасы қанша?» — бұл сұраққа дәптер мүлде жауап бермейді.

Қақтығыс: мәлімет бар, бірақ оны сұрыптау, сүзу және есептеу мүмкін емес. Қорытынды: мәліметті қағазда емес, кестеде сақтау керек — яғни деректер базасында.

Клиенттің нақты қиындығы

Нөмірді іздеу2 мин → 2 сек
Бағаны жаңартуқолмен → UPDATE
Брондау құнын есептеукалькулятор → автоматты
Табыс есебімүмкін емес → JOIN
Қате мәліметжиі → валидация

SQL әдісі DbHelper класында

Не істейді

Нөмірлерді үш режимде іздеу, төрт тәсілмен сұрыптау, жаңа нөмір қосу (валидациямен), баға мен төсек санын жаңарту, нөмірді брондауларымен бірге жою, брондау құнын автоматты есептеу, санаттар мен нөмірлер бойынша статистика шығару.

Неге Android + SQLite

Қосымша ресепшндегі планшетта да, әкімшінің телефонында да жұмыс істейді. База құрылғының жадында — сервер, қосымша төлем, интернет қажет емес. Барлық мәлімет hotel.db файлында.

04 · Архитектура

Қосымшаның құрылымы

Жоба үш қабатқа бөлінген: модель, деректер және интерфейс. Activity кластары SQL жазбайды — олар тек DbHelper әдістерін шақырады.

Модель

Room · Booking

Кестенің бір жолын сақтайтын қарапайым кластар. Room ішінде pricePerBed(), repairAge() сияқты көмекші әдістер бар.

Деректер

DbHelper

SQLiteOpenHelper-ден мұра алады. Кестелерді құрады, бастапқы мәліметті жазады, барлық SELECT / INSERT / UPDATE / DELETE сұраныстарын орындайды.

Интерфейс

4 Activity + 2 Adapter

MainActivity, RoomActivity, AddRoomActivity, StatsActivity; RoomAdapter және BookingAdapter ListView жолдарын құрады.

05 · Деректер базасы

Екі кесте, бір байланыс

DbHelper.onCreate()
db.execSQL("CREATE TABLE rooms ("
  + "_id INTEGER PRIMARY KEY AUTOINCREMENT, "
  + "number TEXT NOT NULL UNIQUE, "
  + "category TEXT NOT NULL, "
  + "floor INTEGER NOT NULL, "
  + "beds INTEGER NOT NULL, "
  + "price INTEGER NOT NULL, "
  + "area INTEGER NOT NULL, "
  + "year_repair INTEGER NOT NULL)");

// екінші кестеде сыртқы кілт бар
  + "FOREIGN KEY(room_id) REFERENCES "
  + "rooms(_id))");

UNIQUE — бір нөмір екі рет қосылмайды. FOREIGN KEY — брондау тек бар нөмірге жасалады.

06 · Негізгі сұраныстар

Тапсырманың үш тармағы — үш әдіс

DbHelper.java · а) санат, ә) қабат + баға, б) орташадан арзан
/** а) Берілген санаттағы барлық нөмірлер. */
public List<Room> byCategory(String category) {
    Log.i(TAG, "а) санат = " + category);
    return readRooms(R_CATEGORY + " = ?", new String[]{category});
}

/** ә) Берілген қабаттағы, бағасы шектен аспайтын нөмірлер. */
public List<Room> byFloorAndPrice(int floor, int maxPrice) {
    Log.i(TAG, "ә) қабат = " + floor + ", бағасы <= " + maxPrice);
    return readRooms(R_FLOOR + " = ? AND " + R_PRICE + " <= ?",
            new String[]{String.valueOf(floor), String.valueOf(maxPrice)});
}

/** б) Бағасы орташа бағадан арзан нөмірлер. */
public List<Room> cheaperThanAverage() {
    int avg = averagePrice();          // SELECT AVG(price) FROM rooms
    Log.i(TAG, "б) орташа баға = " + avg);
    return readRooms(R_PRICE + " < ?", new String[]{String.valueOf(avg)});
}

Неліктен бір ғана readRooms()

Үш әдіс де бір жалпы әдісті шақырады: ол query() орындайды, Cursor бойынша жүріп Room объектілерін жинайды және finally блогында Cursor-ды жабады. Нәтижесінде код қайталанбайды, ресурс ағып кетпейді.

Параметр ретінде «?» белгісі

Мән жолға тікелей қосылмайды, selectionArgs массиві арқылы беріледі. Бұл SQL-инъекциядан қорғайды және апострофтар мен бос орындар бар мәтінмен де дұрыс жұмыс істейді.

07 · CRUD

Қосу, жаңарту, жою

INSERT · ContentValues
ContentValues v = new ContentValues();
v.put(R_NUMBER, number);
v.put(R_CATEGORY, category);
v.put(R_PRICE, price);
long id = getWritableDatabase()
        .insert(T_ROOMS, null, v);
if (id == -1) Log.e(TAG, "INSERT сәтсіз");

insert() жаңа жолдың _id мәнін қайтарады, қате болса −1.

UPDATE · WHERE _id = ?
ContentValues v = new ContentValues();
v.put(R_PRICE, price);
v.put(R_BEDS, beds);
int rows = getWritableDatabase().update(
        T_ROOMS, v, R_ID + " = ?",
        new String[]{String.valueOf(id)});
Log.i(TAG, "өзгерген жол = " + rows);

update() өзгерген жолдар санын қайтарады — 0 болса, мұндай _id жоқ.

DELETE · екі кестеден дәйекті жою
public int deleteRoom(int id) {
    SQLiteDatabase db = getWritableDatabase();
    int bookings = db.delete(T_BOOKINGS, B_ROOM + " = ?", new String[]{String.valueOf(id)});
    int rows = db.delete(T_ROOMS, R_ID + " = ?", new String[]{String.valueOf(id)});
    Log.i(TAG, "DELETE: нөмір _id = " + id + ", онымен бірге " + bookings + " брондау");
    return rows;
}

Алдымен «бала» жолдар (брондаулар), сосын «ата-ана» жол (нөмір) жойылады — әйтпесе базада иесіз жазбалар қалады.

08 · Статистика

GROUP BY және JOIN: сандар сөйлейді

statsByCategory() · GROUP BY ... HAVING
SELECT category, COUNT(*), AVG(price),
       AVG(area), MIN(price)
FROM rooms
GROUP BY category
HAVING COUNT(*) > 0
ORDER BY COUNT(*) DESC, category ASC;
revenueByRoom() · LEFT JOIN
SELECT r.number, r.category, COUNT(b._id),
       SUM(b.nights), SUM(b.cost)
FROM rooms r
LEFT JOIN bookings b ON b.room_id = r._id
GROUP BY r._id
ORDER BY SUM(b.cost) DESC;

13 · Қолдану

Жаңа қызметкер 5 минутта үйренеді

1

Нөмір табу

Режимді таңдап, өрісті толтырып «Іздеу» батырмасын басу. Қорытынды жасыл жазумен көрінеді.

2

Брондау жасау

Нөмірді басып, «Брондау қосу» → қонақтың аты, тәулік және адам саны. Құны автоматты есептеледі.

3

Бағаны жаңарту

Тізімде нөмірді ұзақ басып «Өзгерту» → жаңа баға. База сол сәтте жаңарады.

4

Есеп шығару

Мәзір → «Статистика»: нөмір саны, брондау саны, толу пайызы, орташа/ең арзан/ең қымбат баға, санаттар кесімі және нөмірлердің табысы.

5

Қателессе

Мәзір → «Бастапқы мәліметтер»: база бастапқы 16 нөмір және 12 брондау күйіне қайтады. Сондықтан үйрену кезінде қорықпай эксперимент жасауға болады.
